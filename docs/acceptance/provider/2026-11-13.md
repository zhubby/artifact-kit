## 限流、取消与预算的验证方式

[供应商转发器](../../../tests/operator/acceptance/live_provider.go) 仅在显式启用时
连接固定的 DashScope HTTPS 地址。成功响应保留真实 SSE 内容；验收证据仅记录
状态、时刻、事件数、工具名及参数长度，不保存密钥、请求正文或工具参数正文。
凭据从显式选择的本机私有配置对应的加密 profile 在内存中解密，原开发 profile
不修改；Pi 使用 Runtime 授权，不接收供应商密钥。

429 在转发器中注入一次，之后的成功调用均转发真实供应商。本轮首次拒绝到
再次发送的间隔为 **94.596 秒**：当前实现通过约 90 秒租约到期后换代恢复，
没有按注入响应的 `Retry-After: 2` 立即重试。共享 profile 的 6 RPM 检查使用
两个独立 Pi Pod 的真实发送时刻，未通过大量请求触发供应商限流。

规划取消与期限检查在收到真实供应商的首个非空工具参数片段后，受控暂停向下游
转发，确认 Runtime 撤权或到期会断开流，且不接纳不完整计划。这证明本地代理链路
取消并关闭供应商请求；**不证明供应商服务端停止推理或停止计费**。
预算检查覆盖调用次数和规划期限；SDK usage 不等于供应商账单，断流时可能没有
完整 usage。常规构建的 SDK totalTokens 为 21869，429 恢复构建为 16397；
其中包含 cacheRead，`cost=0` 不能解释为免费。

## 本轮发现与修复

真实供应商生成显式 `shell=sh` 后，首轮任务一直排队。Emissary 使用
`sh --version` 探测，Debian 的 POSIX sh 拒绝该选项，因此错误地上报不可用。
[doctor.rs](../../../crates/emissary/src/doctor.rs) 改用 `sh -c 'exit 0'`
执行能力检查，保留空版本字符串。新增真实子进程回归先失败、修复后通过；
最终供应商计划中的 sh 步骤实际分配给了 Rust Emissary。

第二轮严格 PID 消失检查发现，工作进程已取消，但验收容器直接以 Emissary
作为 PID 1，一个已退出的 `sleep` 子进程残留为 zombie。验收镜像增加 `tini`，
[设备启动方式](../../../tests/operator/acceptance/run.py) 通过 init 启动 Emissary。
最终检查仍要求所有采样 PID 消失；本次进程回收结果基于该容器启动方式。
前两轮均未标记整体通过，诊断保留在私有证据目录；本表七个 Build 全部来自
修复后的最后一轮。

## 重跑与清理

先使用 [prepare.py](../../../tests/operator/acceptance/prepare.py) 构建包含 init
的 arm64 验收镜像，并用 `run.py` 准备专用命名空间及本地 PKI。
已有本任务测试栈时，可运行：

```sh
rtk proxy env KUBECONFIG=.local/operator-cilium/kubeconfig \
  ARTIFACTORY_ACCEPTANCE_IMAGE_TAG=provider-final-1113 \
  python3 -u tests/operator/acceptance/provider.py \
  --context kind-artifact-operator-acceptance-cilium \
  --namespace artifact-operator-telemetry-1113 \
  --profile-env /absolute/path/to/private/env.json \
  --relay-image localhost:5001/artifactory/operator-fixture:provider-final-1113
```

脚本校验保存的 CA 与命名空间归属，要求没有活动构建及设备存在 init，再临时
启用转发器和 maxActive=2。结束时实际读回确认六个测试 profile 全部禁用，
上游容器配置和 AgentPool spec 恢复，无活动测试 Build。额外数据库核验确认
整个命名空间的活动 Build、运行中 attempt、已启用真实测试 profile 均为零；
服务健康，测试栈保留修复后的 Emissary 供查看。

本轮仅验证 Qwen 的 OpenAI Completions 协议及 Linux arm64 容器流程。
