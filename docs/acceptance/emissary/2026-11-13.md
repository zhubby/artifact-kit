## 实现范围

设备执行器更名为 **Artifactory Emissary**，实现位于 `crates/emissary/`。
原 Go 设备代码和生成协议已移除；没有旧名称别名、配置转换或混合版本接入层。
二进制和服务名为 `artifactory-emissary`，配置为 `emissary.json`，
设备 gRPC 包为 `artifactory.emissary.v1`，Rust 生成代码集中在
`crates/emissary-protocol/`。开发数据库从更新后的初始 schema 创建。

控制平面负责权限、计划接纳、构建任务和设备匹配；Kubernetes 中的 Pi
负责仓库分析与规划；设备上的 Emissary 主动出站接入并执行构建、签名和制品上传。
Pi 继续使用 Node.js/TypeScript，`AgentPool`、`AgentRun` 和
`ARTIFACTORY_AGENT_POOL` 仍表示 Pi 资源，不属于设备执行器旧名。

实现覆盖一次性注册与 P-256 身份、固定 CA/TLS 1.3/mTLS、独立 Worker、
单调租约、事件确认与重放、有界磁盘日志、Git/submodule/LFS、签名环境隔离、
受限目录制品上传、Unix 进程组与 Windows Job Object、原生服务管理、
Ed25519 OTA 校验及回滚。控制端、控制台、诊断、发布流程和运维文档同步更名。
API、原测试到 Rust 测试的对应关系见 [PORTING.md](https://github.com/zhubby/artifact-kit/blob/main/crates/emissary/PORTING.md)。

## 本次发现并修复的问题

- 真实业务验收暴露事件重发放大：每次收到确认都重发全部未确认事件，慢确认时
  会挤压后续步骤、完成事件和心跳。新增真实 mTLS 子进程测试，服务端逐条延迟
  50 ms 确认、执行 20 个短步骤；修复前超时失败，修复后通过。现在只发送尚未
  入队的新事件，每五秒或重连后重放未确认内容，重复 accept 限速到每秒一次。
  红 / 绿日志保留在 `.local/emissary-ack-red.log` 和
  `.local/emissary-tests-final.log`；早期业务失败记录保留原状。
- 完成事件的设备失败类型改为 `emissary`，并同步初始 schema 约束；聚焦数据库
  回归先复现旧约束拒绝，再通过修复。未添加旧类型兼容或数据库迁移转换。
- macOS `KeepAlive` 服务停止使用 `bootout`，重启先移除加载的服务再
  `bootstrap`，给 supervisor 留出清理 Worker 的时间。配置包含工作目录和 HOME；
  本轮验证生成配置与进程清理，未在开发宿主安装 LaunchDaemon。
