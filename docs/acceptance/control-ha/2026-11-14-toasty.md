# Control HA 与 main 的 Toasty 整合验收

日期：2026-11-14，Asia/Shanghai。整合基线：`origin/main e18d0ea1cd94473b5fdad149b40f5deae7c6216d`；HA 功能检查点：`a3b9b5f`。

本记录覆盖合并后的 Toasty 实现。合并前的 SQLx 结果保留在 [归档报告](2026-11-14.md)，不能代替本次验证。全部数据库、进程及证书为本次隔离测试创建，未部署、迁移或停止已有环境。

## 整合结果

- 控制平面使用 `crates/control-plane`、`artifactory-control-plane` 及最新 Store 边界；没有重新引入 SQLx。
- 保留 main 的 Build `xmin` 并发保护，汇总仅处理活动 Build，不重复改写历史终态行。
- 在 Toasty 基线 `2026111301` 后追加 `2026111401 / 0001_control_replication.sql`，原子回填在途 assign/cancel 命令，重复迁移保留 command ID 与 lease。
- 专用 LISTEN 会话复用 Toasty 驱动的 URL、启动选项及 TLS 配置，通知缓冲有界；断连重试与定时补偿继续依赖持久命令。每个 Control 的连接预算包含该会话。
- OTA 节点读取使用显式字段，避免新列改变 `SELECT *` 的解码布局；驱动对返回列数不匹配报告错误。
- Telemetry 只读业务授权兼容已知的基线或基线加 HA 两种历史，未知历史及写操作仍拒绝。
- Helm 保留当前 `images/resources/persistence.control-plane`、`agent-worker` 与 `agentWorker` 契约；新增 `controlPlane` 配置多副本、连接预算及排空，Source 使用原 `-control-plane` PVC。

## 三进程故障压测

使用相同的 60 秒窗口、10 秒心跳、SIGKILL / SIGTERM 注入、20 秒连接恢复预算，验收门槛仍为心跳 P99 < 2,000 ms、API P95 < 1,000 ms、至少两轮全量心跳、无最终设备/API 错误、全部原 attempt ID 和运行租约保留。各档依次执行，压测期间不并行运行本次构建或回归测试。

数据库为本次独立 PostgreSQL 17.11 / TimescaleDB 2.32.0 容器，`max_connections=200`、`shared_buffers=4009MB`，`fsync / synchronous_commit / full_page_writes=on`。容器未限制内存，Docker VM 约 15.66 GiB；结果不证明 Helm 示例数据库 4 GiB 限制下的容量。

当前使用标准 release 优化构建，无 Cargo profile 覆盖。三个实际 Control 进程连接独立 schema；设备为独立证书与实际 mTLS 流的虚拟执行器，受控 S3 peer 仅处理初始化。结果不证明真实编译、制品吞吐、遥测采集吞吐、SSE 浏览规模或 Kubernetes 滚动升级。CPU / RSS 为单次快照，不能解释为峰值或生产 SLO。
