## 已验证的行为

- 启动首次提交并 ACK；ACK 丢失重试不改接收时间；普通重连复用快照；新进程完整替换并删除旧字段；旧 session 和退役 startup 均不能覆盖当前数据。
- 自定义内容固定进入 `custom.*`，不能覆盖系统命名空间、labels、签名权限或 slots。新版能力仅随启动快照更新，旧节点继续兼容原有心跳能力更新。
- 64 KiB 快照边界、确定性摘要、最多 8 个候选、资源门槛及两个时间戳的新鲜度校验。cgroup v1/v2、祖先内存限制和缺失指标由受控文件夹具覆盖。
- 官方 MCP SDK 完成 `initialize`、`tools/list`、`tools/call`。Node.js 客户端分别经真实 mTLS gRPC，以及真实 Rust Runtime HTTP 服务、租约验证、内部认证通道到 Control 查询业务数据库。
- Runtime 探针使用测试注册的 Pod 身份获取真实运行租约；验证旧 generation 被拒绝、项目授权撤销后三个工具均不返回设备。本项不包含 Kubernetes TokenReview 或真实 Pod 部署。
- 查询默认 50 台、上限 100 台；按 metadata／工具筛选、稳定游标、128 KiB 响应预算、按需详情、Telemetry 不可用时指标未知、旧启动资源不能参与当前选机。
- 实际调度按候选顺序执行；首选忙碌后使用下一候选；资源变化、过期、能力、metadata 摘要、项目授权、排空、OTA、取消和 slots 均会阻止分配，不使用列表外设备。
- 三个调度器竞争仍遵守任务槽上限。重选轮次持久化，最多两轮、间隔至少 60 秒，每轮调用上限 5 次、截止时间 60 秒；不能放宽原资源要求、修改脚本或变更已分配任务。
- 取消、租约／轮次过期及任务版本变化拒绝迟到提交；Runtime 的 `submit_placements` 与 `submit_plan` 一样具备持久提案去重及旧 generation 隔离。
- viewer 会话可读 metadata；未认证访问、项目 API Token 和不存在节点分别得到相应拒绝／404。节点列表从数据库投影开始就排除完整 metadata。

业务库追加 Toasty 迁移 `2026111402`，Telemetry 库追加 `2026111403`。基线升级、迁移历史检查及 Telemetry 业务只读角色回归通过，既有任务和旧节点继续工作。

## 三副本万台连接故障压测

环境为 macOS arm64、10 个逻辑 CPU、Rust 1.95.0，独立 PostgreSQL 17.11／TimescaleDB 2.32.0 容器。三个真实 Control 进程使用标准 release 构建，每副本数据库连接预算 40。设备使用独立证书和真实 mTLS 流；10,000 台全部提交启动 metadata，重连复用快照；1,000 个活动任务使用虚拟执行器。

测量窗口 30 秒，期间分别强杀一个副本、向另一个副本发送 SIGTERM，检查全部设备向幸存副本恢复。门槛保持心跳 P99 < 2,000 ms、API P95 < 1,000 ms、单设备恢复 < 20 秒、至少两轮全量心跳、最终设备／API 错误为零，以及全部原 attempt ID 和有效运行租约保留。

最终版本通过全部门槛：

| 指标 | 结果 |
| --- | --- |
| 心跳 P99／样本数 | 325.04 ms／32,872 |
| API P95／样本数 | 105.62 ms／280 |
| 恢复数量／最长时间 | 6,667／11.302 秒 |
| 正常／SIGKILL 后／SIGTERM 后心跳 P99 | 199.36／221.93／427.94 ms |
| 最终设备错误／API 错误／可恢复传输重试 | 0／0／88 |

| 数据库连接峰值（含测试端）／锁等待采样峰值 | 133／0 |

所有设备均恢复至幸存副本。其 RSS 快照为 605,712 KiB，CPU 快照为 30.8%。首次建连用时 30.56 秒，测量在全部活动任务进入 running 后开始；首次引导时间不属于 20 秒故障恢复门槛。

[机器可读结果与源码／二进制摘要](2026-11-14-results.json) 保留环境、检查结果、分阶段延迟和验收门槛，不含数据库 URL、证书或凭据。实现阶段和审查阶段的运行日志均保留。审查阶段先检测到镜像自动调优为 `shared_buffers=4009MB`，该轮同样通过；本表采用固定为 `256MB`、包含三项审查修复后的独立复验结果，不挑选不同轮次中的较优指标。

数据库开启 `fsync`、`synchronous_commit`、`full_page_writes`，`max_connections=200`、`shared_buffers=256MB`，测试容器未设置内存限制。该结果不证明 4 GiB 限制下的数据库容量。CPU／RSS 为快照，不是峰值。

压测使用小型 metadata 夹具和受控 S3 初始化端点，不包含真实编译、制品传输、Telemetry 摄取、MCP 并发查询、模型吞吐或 Kubernetes 滚动升级的容量测试。AI 查询／提交链路和资源校验由上面的独立回归覆盖，模型选择流程使用受控响应，不消耗真实供应商调用。

## 复现

使用 Node.js 24，并通过私有环境提供指向可丢弃 TimescaleDB 的 `ARTIFACTORY_TEST_DATABASE_URL`、随机 `ARTIFACTORY_SERVICE_TOKEN`。可用 `ARTIFACTORY_NODE` 指定 Node.js 24 二进制，避免系统默认 Node 版本不同。

```sh
rtk proxy npm --prefix packages/agent-worker ci
rtk proxy npm --prefix packages/agent-worker test
rtk proxy cargo fmt --all --check
rtk proxy cargo clippy --locked --workspace --all-targets --all-features -- -D warnings
rtk proxy cargo test --locked --workspace --all-features
rtk proxy cargo test --locked -p artifactory-control-plane --test database -- \
  --ignored --skip device_fleet_load --test-threads=1
rtk proxy cargo test --locked -p artifactory-telemetry-service -- \
  --ignored --skip telemetry_store_latency --test-threads=1
rtk proxy cargo test --locked -p artifactory-planner-runtime -- --ignored --test-threads=1
rtk proxy cargo test --locked -p artifactory-database -- --ignored --test-threads=1
rtk proxy cargo doc --locked --workspace --no-deps
rtk proxy python3 scripts/check_data_access.py
rtk proxy python3 tests/control/load.py --nodes 10000 --active 1000 \
  --seconds 30 --database-connections 40 --release
rtk proxy npm --prefix web run build
rtk proxy python3 scripts/check_docs.py
```

浏览器回归从 `web/` 执行：

```sh
rtk proxy npm run test:ui -- --project=desktop --project=tablet --project=mobile tests/ui/node-pagination.spec.ts
```
