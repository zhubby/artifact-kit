## 结果

已完成首期实现与独立环境的业务、故障和回退演练：**Rust Source 固定源码 → Kubernetes Pi 分析并提交计划 → Rust 控制平面校验接纳 → 现有 Go Artifactory Agent 构建并登记制品**。真实 DashScope `qwen3.8-max` 链路通过。控制平面继续管理 Build、权限、计划与设备任务；Pi 的心跳、调用预留、检查点进入独立 Runtime，Git 与源码下载进入独立 Source。

项目默认仍为 `poll`；新项目可显式选择 `planner_backend: kubernetes`。未切换既有部署默认路径，未执行生产 migration、Git 提交或远端推送。Substrate 适配及 Rust 设备 Agent 属于后续独立阶段。

## 故障、权限与资源保留

| 场景 | 注入与结果 |
| --- | --- |
| 重复 / 失效 Pod | PostgreSQL 回归验证单 UID、旧 generation/grant 拒绝；集群删除持有模型请求的 Pi Pod，强制其租约到期后进入 generation 2，原 deadline、已用次数和 commit 保留 |
| 模型响应未知 | Runtime 并发测试验证 request ID 重放不再次发送，未知结果仍消耗预算；三种模型协议的路径、认证和 SSE 转发通过 |
| 接纳确认丢失 | fixture 在控制平面完成接纳后返回 503；原 proposal/outbox 重投，没有额外推理和重复 revision/jobs |
| 源码缓存丢失 | 移走 Source 的整个仓库缓存目录，同时令 Git upstream 返回 503；仅从持久对象恢复原 README。PVC 本身保留 |
| Git/tag/LFS 恢复 | Source 的真实 PG/S3 回归恢复固定 commit、annotated tag、LFS 字节，并拒绝被篡改的 LFS 与越界工具路径；原控制平面源码权限/历史快照回归通过 |
| Operator 换主 | 两副本，删除 Lease holder，另一身份接管；mock API 测试验证竞争 CAS、失去读取权限、过期 Lease 与旧 holder 被拒绝 |
| 取消 | 正在等待供应商响应头的运行取消后，Runtime 撤权，Operator 按 Job UID 级联清理 Pod，没有创建设备 jobs；Job 删除确认后仍保留未消失 Pod 的 UID 与 CleanupPending，5 秒重试 |
| Runtime 重启 | 取消、calls=2 及原 deadline 保留；没有预算重置或运行复活 |
| 暂停准入 | AgentPool `maxActive: 0` 进入 Paused，已有运行仍按原 authority 收尾 |
| CRD / RBAC | API server 拒绝修改 AgentRun 不可变上下文；Pi SA 无读取 Secret 权限；未认证 `/metrics` 返回 401 |
| 删除 / 重装 | 卸载独立 Helm release，删除其 SourcePool 后，Source StatefulSet、Service、PVC 的 UID 不变，固定快照仍可读；重新安装后恢复 Ready |
| 终态回收 | Job 显式 Background 级联删除并使用 UID precondition；AgentRun 在清理完成且创建超过 24 小时后回收，清理未完成时保留。dispatcher 标记的 SourceSnapshot 元数据在无运行引用且超过 24 小时后回收；用户声明的资源、DB/S3/PVC 保留 |

表中小负载 Pod 丢失演练通过直接修改测试 Runtime 的 `lease_until_ms` 加速过期；下文最终 100 活动恢复使用自然租约过期，没有改写租约或期限。

新增 `cleanup.py` 对同一故障先红后绿。修复前证据 `20261112-212547-cleanup`：停止 kubelet 并 SIGSTOP 一个真实 Pi 后，Runtime 已 canceled，但进程仍为 T 状态时 Operator 清空了 Pod UID。修复后证据 `.local/operator-load/20261112-213742-cleanup/evidence.json`：约 1.996 秒观察到撤权，3.810—40.941 秒的 8 次采样均保留 canceled、CleanupPending、原 Pod UID 与暂停进程；恢复后确认 kubelet 可用、Pi PID 消失、Pod/状态清理完成，calls/deadline 不变且无设备 jobs。测试使用独立 Docker/API 恢复通路，不依赖已停止 kubelet 的 exec/port-forward。该窗口 Node Ready 仍为 True；这是已验证的 kubelet 不可达故障，完整网络分区与 API 强制删除后的远端物理停止不在此结论内。

该次取消观察值：API 返回 0.013 秒、Runtime canceled 状态被观察到 2.906 秒、Pi Pod 被清理 6.367 秒，均从取消请求开始计时。状态轮询时间是观察上界，不能推断跨节点分区时延。

本次修复了 Git Basic challenge 缺失、重复 cancel 的意图 hash、终态 acquire、供应商响应头前取消、Pi 将连接中断误报终止、Kubernetes Job 默认 orphan 删除等问题。对应回归已通过。
