# Zero-intrusion AI builds implementation plan

User-approved scope: Pi Agent Core SDK produces structured execution plans from
platform-cached source. Upstream repositories stay read-only and need no
artifactory.yaml or Pi files. Commands and external scripts only; at most two
automatic revisions per build. Preserve existing data, identities and rename work.

- [x] Persistent Git, submodule and LFS snapshots; authenticated read-only distribution.
- [x] Agent source cache, external scripts and tracked-source mutation checks.
- [x] Encrypted model profiles, mTLS planner enrollment and fenced planning leases.
- [x] Pi SDK worker with read-only tools, per-task process and bounded model calls.

- [x] Console, Chinese/English copy, Compose, Helm, local services and docs.
- [x] Automated regression and isolated live Pi/source/build acceptance.
- [x] Backed-up deployment and acceptance locally and on codehubmac-mini.

## Technical decisions

- Pi packages @earendil-works/pi-agent-core and pi-ai are pinned to 1.5.2; Node 24.
- Source credentials stay in control-plane. Scoped source tokens authorize only a live
  attempt. Git receive-pack is disabled. Source HTTP bypasses the Next proxy.
- Source snapshots include root commit, frozen tags, submodule graph and LFS OIDs.
- Agent workers read source through platform tools without cloning or loading repo code.
- Platform owns model configuration; only task children receive plaintext secrets.
- Existing Recipe validation is reused as the typed execution-plan validator.
- Attempts bind a source snapshot and immutable plan revision; stale results reject.
- Retries retain commit and plan; revisions change only failed targets.
- Generated build output is allowed; tracked-file or submodule changes fail the step.
- Old build/configuration records remain readable and retain their retry semantics.
