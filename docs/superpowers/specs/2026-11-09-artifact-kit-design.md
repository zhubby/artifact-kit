# Artifact Kit 设计基线

> 历史设计与计划归档。本文保留当时的决策和实施背景，不作为当前功能清单；实际结果以对应版本的源码与验收记录为准。

日期：2026-11-09。状态：用户已在设计对话及实施请求中确认。

## 产品与边界

面向个人或内部可信团队，围绕项目、构建、制品、Release 组织，不复刻通用 CI。
Linux、macOS、Windows 是 Agent 宿主；Linux、macOS、Windows、Android、iOS 是应用目标。
首版使用原生执行器、项目脚本签名和内部分发；不提供不可信代码沙箱。
容器执行器和 OCI 制品分别扩展；Webhook、官方商店、OIDC、多实例高可用不属于首版。

## 架构

- Rust/Axum/Tonic 模块化单体控制中心，Linux 单实例部署。
- PostgreSQL 持久化身份、配置、节点、队列、执行租约、制品索引、发布与审计。
- S3 兼容对象存储保存制品与日志，桶不公开。
- Go Agent 主动连接，独立 Worker 执行任务；系统服务支持 Linux、macOS、Windows。
- Next.js/React/shadcn/Tailwind 提供控制台，业务授权由 Rust 统一执行。

## 身份

内置管理员、操作者、只读角色。API Token 限项目及 read/build/release 操作。
管理员创建节点注册令牌、配置源码凭据、授权节点池和签名引用。
注册使用服务端 TLS 加一次性短期令牌；其余 Agent RPC 强制 mTLS。
节点证书指纹和有效期在数据库中检查；吊销后停止续租。
签名私钥只保存在专用节点。Git 凭据 AES-GCM 加密，主密钥不在数据库。

## 配置与构建

仓库根目录使用版本化 artifact-kit.yaml。中心将引用解析为确切提交，保存配置快照及参数。
Agent 拉取相同提交，逐目标执行有超时的 build/sign/verify 步骤。
配置可声明目标宿主、架构、能力、标签、参数、制品规则、签名引用和发布规则。
只允许 native 执行器，不接受未实现的容器能力，不接受未知配置字段。
每个签名目标必须声明 sign 和 verify 阶段，引用必须经过项目及节点双重授权。

## 调度与失败

节点默认并发 1。调度按项目池、OS/架构、标签、工具链、签名引用及空闲槽位匹配。
PostgreSQL 事务、行锁和 SKIP LOCKED 防止并发领取同一任务。
10 秒心跳，90 秒执行租约；Worker 使用单调时钟执行本地截止期限。
短暂失联可续接；租约过期终止整个进程树，标记 lost，不自动重试已开始任务。
未开始且租约过期的任务可重新排队；显式重试产生新的 attempt。
状态：queued/leased/running/succeeded/failed/canceled/lost。
attempt ID、租约凭证及事件序号用于 fencing、去重和重连；迟到结果不能覆盖当前状态。
Agent 崩溃或控制管道关闭也必须终止 Worker 的任务进程树。
中心重启保留在途租约，不立即重派任务。

## 日志、制品与发布

控制流、日志上传分别使用 gRPC 连接；文件使用短期授权 HTTPS。
日志分块有序，确认后推进上传位置，本地缓冲有界，耗尽必须明确报告。
按 attempt 隔离目录；拒绝绝对路径、上级路径和链接制品；清理只在受管目录内执行。
服务端实际读取上传对象并计算大小、SHA-256，匹配后才登记制品。
所有必需目标及签名校验成功后才能发布。构建和发布状态分别持久化。
内部 Release 原子可见、不可变、版本名项目内唯一，重复发布使用幂等键。
发布失败可复用已验证制品重试，不必重新构建或重新签名。
内部下载不等于设备安装授权；iOS 等仍受原生签名、设备及分发规则约束。

## 控制台与运维

项目、构建矩阵与日志、节点能力与租约、制品、Release、凭据引用和审计。
不提供伪造机器、构建进度、签名成功或发布成功的演示数据。
Compose 只部署控制面；Agent 原生安装，不使用 Docker socket 代替宿主能力。
升级先排空再手动更新；诊断不自动安装 SDK。

## 验收

必须测试真实 Rust/Go 协议互通、真实 PostgreSQL 的并发调度和租约恢复、S3 完整性、鉴权、幂等发布。
故障包括断线、中心重启、证书吊销、取消、Agent 崩溃、重复消息、迟到结果、日志缓冲耗尽。
真实构建与签名需要相应实体机、SDK、证书和设备；缺失项明确记为未验收。
交叉编译通过不等于 Windows/Linux 运行通过；工具存在不等于原生应用可用。
